# Contributing

## Development Workflow

This repository uses a pull request based workflow.

Recommended branch prefixes:

- `feat/`
- `fix/`
- `docs/`
- `test/`
- `refactor/`
- `ci/`
- `chore/`
- `security/`

## Pull Requests

Pull requests should include:

- clear summary
- list of changes
- verification steps
- security impact when relevant
- database impact when relevant
- screenshots when UI changes

## Code Quality

When the application tooling is available, changes should pass the relevant quality checks:

- backend tests
- frontend type checks
- build checks
- code style checks
- static analysis

## Documentation

Architecture, security, and database changes should be documented when they affect project behavior or long-term maintenance.
